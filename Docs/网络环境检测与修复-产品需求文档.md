# 网络诊断（网络环境检测与修复）产品需求文档

- 版本：v1.0（已评审通过，定稿）
- 负责人：产品经理
- 状态：定稿，待功能拆分
- 评审结论：2026-08-04 需求方（姚森林）审核通过
- 关联模块：Shell（侧边栏导航）、Dashboard、SettingsView、Toast、确认弹窗、语言包

## 1. 背景与问题

用户最常见的故障场景之一就是"突然上不了网"。断网发生时，用户通常的做法是：

1. 打开浏览器反复刷新（无效）；
2. 手动打开命令行执行 `ipconfig /flushdns`、`ping` 等命令——命令记不全、不知道先做什么后做什么；
3. 重启路由器/重启电脑（重武器，成本高）；
4. 依赖 Windows 自带的"网络疑难解答"，但它只做浅层检查，且对 DNS / 代理 / Winsock 等常见问题定位能力弱，修复提示晦涩。

ToolBox 是常驻托盘、可全局热键唤起的效率工具箱，天然适合承载"一键检测 → 定位 → 修复"这类高频、低延迟、本地可完成的诊断任务，把用户从"记命令"和"百度搜索"中解放出来。

**核心问题**：网络故障排查链路长、命令专业门槛高、修复动作不可见，用户缺少一个本地、可解释、可一键执行的诊断工具。

## 2. 目标与成功指标

### 目标
1. 用户断网后，能在 **1 次操作**（唤起工具箱 → 点「一键诊断」）内获得明确的故障定位；
2. 可自动修复的故障（DHCP 异常、DNS 缓存/配置异常、Winsock 损坏等）能在应用内一键修复，**无需打开命令行**；
3. 每次修复前后有对比验证，用户能看懂"修了什么、修好没有"。

### 成功指标（可测量）
| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 一键诊断耗时 | ≤ 10s（本地检测） | 埋点 |
| 自动修复成功率 | ≥ 80%（可修复类型中） | 修复后验证通过率埋点 |
| 诊断结论可读率 | 诊断结果页面 0 个未解释的命令行原文（全部翻译为自然语言） | 人工抽查 |
| 修复操作回滚/确认率 | 所有涉及系统配置的修复均需用户确认 | 埋点审计 |

## 3. 用户故事

- **US1**：作为普通用户，我断网后唤起工具箱点「一键诊断」，希望知道"到底哪里坏了"。
- **US2**：作为用户，检测出 DNS 有问题时，我希望能一键"刷新 DNS 并切换为公共 DNS"，而不是去命令行敲 `ipconfig /flushdns`。
- **US3**：作为用户，修复后我希望看到"修复前 → 修复后"的对比，确认问题真的解决。
- **US4**：作为公司网用户，我希望诊断器能识别"代理配置异常"导致的断网，而不是让我瞎试。
- **US5**：作为用户，我希望诊断全程离线可用，不把我的网络信息上传到任何服务器。
- **US6**：作为用户，当问题无法自动修复（如网线没插、Wi-Fi 断开）时，我希望得到明确的下一步操作指引。

## 4. 功能范围

### In scope（本期）

| 编号 | 功能 | 优先级 |
|------|------|--------|
| F1 | 一键诊断入口（侧边栏模块 + 托盘菜单 + 全局热键 + 仪表盘快捷卡片） | Must |
| F2 | L1 连通性检测：活动适配器、网关连通、DNS 解析、外网连通（分级展示） | Must |
| F3 | L2 配置检测：IP 地址合法性、DNS 服务器配置（自动/静态、空值、可达性）、系统代理设置 | Must |
| F4 | 问题定位与结论：输出自然语言根因 + 对应修复建议，按严重度排序 | Must |
| F5 | 自动修复（逐项确认）：刷新 DNS 缓存、释放/续租 DHCP、重置 Winsock、重置 TCP/IP、切换为公共 DNS | Must |
| F6 | 修复验证：修复后自动重跑 L1，展示前后对比 | Must |
| F7 | 检测/修复日志：最近 10 次诊断记录，含时间、结论、执行动作 | Should |
| F8 | 管理员权限处理：修复命令的提权引导（见 5.5 与风险） | Must |
| F9 | 双主题适配 + 中英双语（Lang zh-CN / en-US） | Must |

### Out of scope（明确不做）
- ❌ Wi-Fi 信号强度管理、无线网络扫描与切换
- ❌ VPN / 代理客户端的创建与管理
- ❌ 局域网设备发现、路由器管理
- ❌ 网络测速（Speedtest）
- ❌ 云端上传诊断日志、远程协助
- ❌ 后台自动诊断与自动修复（隐私与误操作风险，仅提供手动触发）
- ❌ 第三方诊断工具集成

## 5. 交互设计

### 5.1 入口与信息架构

新增侧边栏导航条目「网络诊断」（图标建议用链路/信号类图标），位于「OCR」之后、「设置」之前，不改动现有导航分组。

| 入口 | 行为 |
|------|------|
| 侧边栏「网络诊断」 | 打开诊断主视图 |
| 托盘菜单「网络诊断」 | 打开主窗口并跳转到该视图 |
| 全局热键（SettingsView 可配置，默认 `Ctrl+Alt+N`） | 唤起工具箱并打开该视图 |
| 仪表盘快捷卡片 | 与其它模块卡片一致，点击进入 |

### 5.2 主视图（诊断页）

**布局**（自上而下）：
1. **状态区**：当前网络状态概览（正常/异常 + 一句话结论），大字号（标题 18）；
2. **操作区**：主按钮「一键诊断」（BtnPrimary）与次级按钮「重新检测」（BtnDefault，诊断完成后出现）；修复类操作在结果区逐项出现；
3. **检测结果列表**：每行一个检测项，左侧状态图标 + 检测项名称（Section 11 SemiBold）+ 右侧详情/说明（辅助 11）。行内无隐藏交互，点击行展开详情面板（诊断详情、涉及配置项、对应修复按钮）；
4. **修复区**：需要修复时展示「修复建议卡片」，含影响说明 + 「执行修复」按钮 + 「稍后处理」；
5. **日志区**：最近诊断记录（F7），折叠式。

**空状态**：首次进入，无历史记录时，检测列表显示引导文案"点击「一键诊断」开始检查网络环境"，不展示空表格。

### 5.3 检测状态机（模块级）

```
Idle ──(点击一键诊断)──▶ Diagnosing ──(全部完成)──▶ DiagnosisDone
                                                        │
                                          ┌─────────────┴─────────────┐
                                          ▼                           ▼
                                       Healthy（全绿）            IssuesFound（有 Fail/Warning）
                                          │                           │
                                          ▼                           ▼
                                      Idle（可重测）           Unrepairable（全手工项）
                                                                        │
                                                                        ▼
                                                           Repairing（用户确认后）
                                                                        │
                                                                        ▼
                                                              RepairDone ──▶ 自动重测 ──▶ DiagnosisDone
```

### 5.4 检测项状态（行级）

| 状态 | 图标语义 | 说明 |
|------|----------|------|
| Pending | 灰（辅助色） | 待检测 |
| Testing | 旋转指示 | 进行中 |
| Pass | 成功绿 | 检测通过 |
| Fail | 失败红 | 检测失败，是当前故障根因（或候选） |
| Warning | 警告橙 | 非致命但影响体验（如外网探测超时但内网正常） |
| Skipped | 灰 | 因前置失败而跳过（如无活动网卡则不测网关） |

### 5.5 修复流程（关键交互）

1. 用户点击「执行修复」→ 弹出**确认弹窗**（复用待办模块的确认弹窗范式），内容含：修复动作名称、涉及的系统配置项、影响说明（"将短暂断开当前网络连接约数秒"）、[取消/执行]；
2. 确认后进入修复执行态：列表逐项展示进度与输出摘要（自然语言，不展示原始命令行洪水）；
3. **管理员权限（R6 已定稿）**：`ipconfig /release`、`/renew`、`netsh winsock reset`、`netsh int ip reset`、修改静态 DNS 均需要管理员权限。采用**单次批处理提权**方案：
   - 权限预检：执行前检测当前进程是否已提权（`IsAdministrator`）；已提权则跳过 UAC 直接执行；
   - 单次 UAC：未提权时，本次诊断会话内**所有**需提权的修复动作打包进一个提权子进程（`ProcessStartInfo.Verb = "runas"` + stdout 重定向）按序执行，全程仅弹一次 UAC；进度与输出摘要实时回传到主 UI；
   - 降级路径：UAC 被取消或当前账户无管理员权限时，不静默失败——修复区切换为「手动修复引导」：逐条展示命令 + "以管理员身份打开 PowerShell 执行"指引，对应修复项标记"未完成"，日志记录"提权被取消"；
   - 明确不采用：全应用管理员模式（安全面扩大、需重启、托盘/热键/剪贴板冲突风险）与计划任务提权（企业策略可能禁用、杀软误报）。
4. 修复完成后自动重跑 L1 检测（F6），展示对比：每个修复项前 → 后状态；
5. 修复成功/失败均弹 Toast 通知（复用颜色工具 Toast 范式），并写入日志区（F7）。

**修复项清单（本期支持）**：

| 修复项 | 触发条件 | 动作 | 影响 |
|--------|----------|------|------|
| 刷新 DNS 缓存 | DNS 解析失败 | `ipconfig /flushdns` | 无断网，秒级 |
| 释放并续租 DHCP | IP 为 169.254.x.x 或网关不通 | `ipconfig /release` + `/renew` | 短暂断网约数秒 |
| 重置 Winsock | 疑似协议栈损坏（多次诊断反复失败且无明确配置问题） | `netsh winsock reset` | 需重启电脑后完全生效（提示） |
| 重置 TCP/IP | 同上，与 Winsock 组合提供 | `netsh int ip reset` | 需重启电脑后完全生效（提示） |
| 切换为公共 DNS | DNS 为空/不可达/超时，且用户确认 | 将当前网卡 DNS 设为静态（可选 223.5.5.5 / 119.29.29.29 / 1.1.1.1，默认阿里 DNS） | 无断网；**修改前备份原配置，提供「恢复原 DNS」入口** |

> 注：以上命令行仅为开发参考（Windows 10/11 能力），具体实现由前端工程师以系统 API / 命令行方式落地，本 PRD 只定义行为与验收。

### 5.6 诊断结论措辞规范

- 结论必须为自然语言，禁止直接展示命令原文或代码块；
- 失败项必须给出"原因 + 影响 + 建议动作"三段式；
- 多故障时按严重度排序：适配器不可用 > IP 异常 > DNS 异常 > 代理异常 > 外网不可达（Warning 不参与排序）。

## 7. 验收标准（Given/When/Then）

### 正常路径
- **AC-01**：Given 网络正常，When 用户点击「一键诊断」，Then 10s 内完成，全部检测项 Pass，结论显示"网络环境正常"，无修复区。
- **AC-02**：Given 网卡已连接但 DNS 配置为空，When 用户点击「一键诊断」，Then 诊断列表展示 DNS 检测项 Fail，结论为"DNS 服务器未配置"，修复区出现「切换为公共 DNS」与「重置 DNS 为自动获取」两项。
- **AC-03**：Given 上一条中用户点击「执行修复（切换公共 DNS）」，When 确认弹窗点「执行」，Then 执行进度可见，完成后自动重跑 L1，DNS 检测项变 Pass，Toast 提示修复成功。
- **AC-04**：Given IP 为 169.254.x.x（DHCP 获取失败），When 一键诊断，Then 结论为"未能从路由器获取 IP 地址"，修复区出现「重新获取 IP 地址（DHCP 续租）」。
- **AC-05**：Given 系统代理开启但代理不可达，When 一键诊断，Then 检测项「系统代理」Fail，结论给出"代理服务器无法连接"及引导（检查代理地址或关闭代理），**不自动修改代理设置**（Out of scope 的操作不做）。

### 边界与异常
- **AC-06**：Given 无任何活动网络适配器（Wi-Fi 关闭且无网线），When 一键诊断，Then 显示适配器检测 Fail，后续项 Skipped，结论为"未检测到可用的网络连接"，修复区不出现任何修复按钮，改为操作指引（打开 Wi-Fi / 插入网线）。
- **AC-07**：Given 所有可自动修复的项都已修复但网络仍不通，When 再次诊断仍 Fail，Then 提示"需要管理员权限的深层修复（重置网络协议栈）"并提供入口；用户确认后进入提权流程（见 AC-15/16）。
- **AC-08**：Given 用户取消了「切换公共 DNS」，When 修复流程中止，Then 系统配置不发生任何变更，日志记录"用户取消"。
- **AC-09**：Given 首次进入且无历史记录，When 打开网络诊断视图，Then 显示引导空状态，不出现空表格。
- **AC-10**：Given 诊断/修复过程中用户切换主题（Light↔Dark），When 页面重新渲染，Then 所有状态色在两种主题下均可读（对比度达标），无硬编码颜色。
- **AC-11**：Given 语言设置为 en-US，When 打开网络诊断，Then 全部文案（含诊断结论、修复项、Toast）为英文，无中英混排。
- **AC-12**：Given 修复动作执行中（如 DHCP 续租），When 用户关闭工具箱窗口，Then 修复进程不中断，完成后写入日志与 Toast（进程不因窗口关闭被杀）。
- **AC-15**：Given 本次诊断会话需要 3 个提权修复动作且进程未提权，When 用户确认执行，Then 全程仅弹一次 UAC，全部动作在同一提权子进程中按序执行，进度实时回传，不再弹第二次 UAC。
- **AC-16**：Given 用户取消 UAC 或当前账户无管理员权限，When 尝试执行提权修复，Then 不静默失败：修复区切换为手动修复引导（逐条命令 + 以管理员身份打开 PowerShell 指引），对应修复项标记"未完成"，日志记录"提权被取消"。
- **AC-17**：Given 工具箱已以管理员身份运行（进程已提权），When 用户执行修复，Then 不触发 UAC，直接执行全部修复动作。

### 数据与隐私
- **AC-13**：Given 用户完成一次诊断，When 查看日志区，Then 显示最近 10 次记录，含时间、结论、执行的动作；日志仅存本地。
- **AC-14**：Given 用户使用诊断功能，When 全程联网状态，Then 应用不上传任何网络诊断数据；检测过程可完全离线完成。

## 8. 非功能需求

### 8.1 性能
- 一键诊断总时长 ≤ 10s；单探测超时 ≤ 3s，并行执行可并行的检测项；
- 诊断期间 UI 不阻塞（后台线程执行，结果增量渲染）；
- 常驻内存增量 ≤ 30MB（诊断模块加载后）。

### 8.2 兼容性
- Windows 10（1809+）与 Windows 11；
- 支持 DHCP / 静态 IP、有线 / Wi-Fi、代理开启与关闭场景；
- 检测命令不可用时（企业策略禁用）给出降级提示，不崩溃。

### 8.3 离线与隐私
- 全流程离线可用；外网连通性探测作为独立可选环节（结果仅为 Warning 级，不阻断结论）；
- 外网探测目标：默认 `baidu.com`（已与需求方确认），可在 SettingsView 中修改或关闭；
- 无任何云端依赖；日志与配置仅本地存储。

### 8.4 本地化与错误码
- 引入错误码体系（如 `NET-101 网关不可达`、`NET-201 DNS 未配置`），错误码进日志，展示文案走语言包；便于后续扩展语言与排查。

### 8.5 可维护性
- 检测项与修复项以"诊断器（Checker）+ 修复器（Fixer）"插件式注册，新增检测项不改动主流程。

## 9. 风险与开放问题

| 编号 | 风险/问题 | 影响 | 缓解/决策 |
|------|-----------|------|-----------|
| R1 | 修复命令需要管理员权限，UAC 弹窗打断体验 | 高 | 已定稿：单会话单次 UAC（批处理提权）+ 权限预检；UAC 取消/无权限时降级为手动修复引导（见 5.5 节） |
| R2 | `netsh winsock reset` 需重启电脑才完全生效，用户可能误以为未修复 | 中 | 执行前确认弹窗中明确提示"需重启电脑"，修复后结论明确标注"待重启生效" |
| R3 | 企业网络/公司代理环境误判"代理异常" | 中 | 代理检测只报 Warning 并提供引导，不做自动修改（AC-05 已固化） |
| R4 | 切换公共 DNS 与公司内网解析冲突 | 中 | 修改前备份原 DNS 配置，提供「恢复原 DNS」入口；默认推荐"重置为自动获取"优先于"公共 DNS" |
| R5 | 误操作导致系统网络配置被改 | 高 | 所有修复均需确认弹窗 + 影响说明；日志可追溯；提供恢复原配置能力（DNS 场景） |
