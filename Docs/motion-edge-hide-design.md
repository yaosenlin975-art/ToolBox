# ToolBox 动效与靠边隐藏优化设计

状态：用户已确认，代码实施、Release 构建及自动检查通过；交互观感待人工验收。日期：2026-10-08。

## 需求分析与现状

目标是让常用操作有连续、明确的反馈，并让迷你窗口的靠边收起可以预测、随时撤回；维持现有 Light/Dark 配色与紧凑布局。

源码证据：
- `Project/Views/CompactToolboxWindow.xaml.cs`：`SwitchToTab` 直接切换 Visibility；`TodoCollapse_Click` 直接改变高度；`Window_MouseLeave` 使用 2 单位贴边阈值，固定等待 5 秒。
- 同文件 `ShowWindow/HideWindow`：Left 动画固定 300ms，另用 310ms DispatcherTimer 判定结束；动画期间基本拒绝操作，只在唤起条进入时记一次恢复请求。
- 同文件 `GetCurrentMonitorWorkArea`：直接把 Win32 rcWork 物理像素当作 WPF 逻辑坐标，与 Left/Width 比较，未转换 DPI，也未检查 GetMonitorInfo 返回值。
- `Project/Views/CompactToolboxWindow.xaml`：隐藏开始就显示全高 20px 竖条，同时关闭内容命中；主体仍可见时已不能操作。
- `Project/Views/WorkbenchWindow.xaml.cs`：`LoadPage` 直接替换 PageHost.Content。
- `Project/Themes/DesignTokens.xaml`：主按钮模板的 hover 主要是直接改色；现有 PreviewCard 已使用 WPF Storyboard、透明度和位移过渡，可复用实现方式。

以上为静态分析；实际帧率、拖动手感和高 DPI 表现尚需运行验证。不能把所有 Duration=0 都当成缺陷：部分控件已有 VisualTransition。

## 方案选型

1. 仅调整时长和缓动：改动少，但不能解决计时器竞态、坐标错误和不可打断，故不采用。
2. **推荐：沿用 WPF 原生动画，修正靠边交互，再补核心场景过渡。** 无新增 NuGet 包；复用 DoubleAnimation、Storyboard、现有主题资源。属于既有功能修改，不引入新的动画系统。
3. 引入第三方控件/动效库：本次需求没有原生能力缺口，且仍需自行处理窗口坐标与隐藏规则，不建议迁入。

不新增通用动画框架、不替换现有窗口皮肤、不加入弹跳/长距离飞入、不对每次列表刷新播放入场动画。

## 动效规格（初始调校值）

| 场景 | 推荐表现 |
| --- | --- |
| 主按钮 hover / 按下 | 100–140ms 状态层淡入淡出；按下使用轻微视觉反馈，避免文字缩放模糊 |
| 工作台页面 / 迷你标签切换 | 新内容 150–180ms 淡入，伴随 4–6 DIP 位移；旧内容直接移除，不叠两棵页面树 |
| 迷你待办折叠 / 展开 | 160–200ms 高度过渡，保持窗口底部或已锁定停靠位置；到终点再提交布局状态 |
| 边缘收起 / 展开 | 约 180ms / 220ms，平滑减速；中途反向从当前位置续接，不回到起点 |
| 系统关闭动画效果 | 遵循 SystemParameters.ClientAreaAnimation，立即提交最终状态 |

控件内容动作不等待动画完成；同页重复点击、CLI 引起的普通列表更新不重复播放页面入场。动画结束清除动画时钟并写入最终基础值，防止样式/布局后续更新失效。

## 靠边交互与关键流程

仅处理左右边缘，使用当前显示器工作区，避开任务栏；不扩展上下边缘或跨窗口吸附。

1. 拖动期间取消收起。拖动结束后距离左右工作区边缘不超过 12 DIP 时轻微吸附，记录停靠侧；离开边缘后清除停靠侧。显示器内部接缝不自动隐藏；左右任务栏所在侧也不收起，避免滑到邻屏或覆盖任务栏。
2. 已停靠窗口在鼠标离开约 800ms 后收起；鼠标回来立即取消。隐藏前重新检查仍贴边、窗口可见、无拖动/鼠标捕获、无菜单或弹窗交互。
3. 隐藏后保留 12 DIP 可命中区域，视觉上只显示窄握柄；沿用当前窗口的局部区域，不额外遮挡屏幕整条边。
4. 悬停握柄约 120ms 后展开，点击立即展开；鼠标快速经过后离开则取消唤起。展开不主动抢键盘焦点，显式点击/托盘调用按原激活行为处理。
5. 收起中鼠标重新进入、或出现显式恢复请求，立即反向展开；展开中不触发再隐藏。结束后重新判断指针是否在窗口外，必要时重新进入离开等待。
6. 关闭自动隐藏、切换到工作台、隐藏整个迷你窗口、关闭应用时，取消等待和动画，提交一致的可见位置/命中状态；旧回调不能覆盖新状态。
7. DPI、显示器或工作区变化后重新解析停靠位置并约束到可用区域；断开显示器时保证窗口可召回。

## 接口与数据结构

- 保留 `ApplyAutoHide(bool)`、`SwitchToTab(string)` 和外部 Show/Activate 调用契约；恢复逻辑需覆盖 OnActivated 及窗口重新显示。
- 在迷你窗口内用明确枚举代替互相覆盖的布尔组合：`Visible / HidePending / Hiding / Hidden / Showing`，另存 `DockSide(None/Left/Right)`。
- 每次转换撤销上一等待/动画，动画完成使用 Completed 事件和转换序号校验，不再另建 310ms 完成计时器。进入新状态前采样当前位置作为动画起点。
- 坐标计算在同一坐标系进行：Win32 工作区与 HWND 矩形在物理像素中比较，通过当前窗口的 WPF DPI 变换提交位置；监视器信息读取失败使用安全回退，不能拿零工作区继续动画。
- 保留现有 AutoHideEnabled 持久化字段；时长、边缘阈值和握柄宽度先用集中常量，不新增一页调参配置或数据迁移。
- 少量通用动效时长/位移值放现有 DesignTokens；具体窗口流程仍归原窗口负责。动画使用现有 DynamicResource 配色，不动画修改共享主题 Brush 实例。

## 实施范围与验证

优先完成迷你窗口状态、DPI 与可打断隐藏，再补工作台页面、迷你标签/折叠及主按钮反馈。主要涉及 CompactToolboxWindow.xaml/.cs、WorkbenchWindow.xaml/.cs、DesignTokens.xaml；若发现必须修改直接调用者，再限定扩展。

不改现有 Todo 数据、CLI、截图与剪贴板功能，也不碰其他未提交改动。

验证覆盖：
- 低成本状态/坐标检查：左右边缘、负坐标显示器、100/150/200% 缩放、旧动画完成回调不覆盖新转换。
- 人工交互：快速进出握柄、收起中反向、拖动和尺寸变化、菜单/详情交互时不误藏、禁用隐藏立即恢复、工作台来回切换、应用退出。
- Light/Dark、系统关闭动画、连续切页均无残影和不可点击区域；开关和复用窗口行为保持一致。
- 在实际窗口记录观感和卡顿；同步加载截图/重建 Todo 列表可能阻塞 UI 线程，动画本身不能消除这类停顿。只有运行证据指向它们时，再单独确定优化边界。
