# ToolBox Task CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. 本次按用户指定的 executing-plans 执行，父代理负责架构和启动，边界明确的实现交给 Luna。

**Goal:** 外部脚本通过 CLI 安全操作原 ToolBox 待办，应用关闭时自动启动无窗口后台实例。

**Architecture:** Console 客户端通过当前用户命名管道连接唯一 ToolBox 实例，后台与 UI 共用 TodoStore。原 JSON 文件保持原位置和结构，Store 锁内验证/变更/快照，原子提交并在失败时回滚。

**Tech Stack:** .NET 8 Windows、WPF、System.CommandLine 2.0.2、System.IO.Pipes、System.Text.Json。

**Spec:** `Docs/task-cli-design.md`（用户已授权实施，命令解析已改选 System.CommandLine）。

## Global Constraints

- 代码全部位于 `Project/`，不修改 `refs/`，不另建 solution。
- IPC 仅本机当前用户，最大请求/响应各 4 MiB，启动 10 秒、请求 30 秒上限。
- 沿用 `%APPDATA%/ToolBox/todos.json` 和现有全局 Mutex，CLI 不直接写数据文件。
- `delete` 为回收站；日期必须带时区；省略字段保持原值，显式 null 只可清空 dueDate。
- stdout 单个 JSON、stderr 诊断、退出码 0/2/3/4/5/6/7；写入发送后失败不得自动重放。
- System.CommandLine 固定 2.0.2，只在 CLI 引用并附 MIT 许可；不新增渲染/DI/RPC 依赖。
- 不改 LLM 提示词、文件访问白名单、会话持久化或无关 UI。

## Review Focus

- 并发冷启动应仅存活一个 host，之后双击提升原实例而非开第二个写入者（任务 3 集成检查）。
- UI 持有 TodoItem 引用时保存失败，回滚须恢复原对象而非留下过期引用（任务 2 故障注入）。
- 递归回收站操作只提交一次，树和提醒不能部分成功（任务 2 子树检查）。
- 客户端发送写入后断连不得重复 create，响应应提示结果未知（任务 1 运输故障检查）。
- 后台停止、旧版占 Mutex、同用户不同提权级别不可静默绕过 IPC（任务 3 生命周期/访问检查）。
